# 自動テスト戦略

## 1. 必須方針

コードの追加・変更には自動テストを必須とします。ビルド成功、手動目視、実機確認はそれぞれ別の証拠であり、自動テストの代替にはしません。

完了条件は次のとおりです。

1. 変更した公開メソッドにCUIテストがある。
2. 複数条件の組み合わせで結果が変わる処理にはCT観点がある。
3. `npm run verify` が成功する。
4. UI変更は自動テストに加えて通常幅・狭幅を目視する。
5. OS通知など自動化できない確認は、未確認事項として分離して報告する。

## 2. CUIテスト

このリポジトリでのCUIテストは、GUI操作に依存せずコマンドラインから反復実行できる、公開メソッド単位のテストを指します。

- 配置: `tests/cui/`
- 実行: `npm run test:cui`
- 対象: `src/lib/` の公開メソッド、入力検証、DBクエリと変換、エラー境界
- DBアクセス: Tauri SQL境界をモックし、SQL、引数、呼び出し順、返却値変換を確認する
- 新しい公開メソッドを追加した場合、正常系だけでなく代表的な拒否条件も追加する

カバレッジは `src/lib/calendar.ts`、`src/lib/wbs.ts`、`src/lib/projects.ts` を対象とし、関数100%、行・文85%以上、分岐75%以上を必須にします。

## 3. CT（組み合わせテスト）

CTは、因子と水準を定義し、境界値を含む組み合わせで共通の不変条件を確認するテストです。

- 配置: `tests/ct/`
- 実行: `npm run test:ct`
- テストファイルに因子、水準、組み合わせ方をコメントで残す
- 全組み合わせが過大な場合はペアワイズを基本とし、安全・永続化に関わる条件は必要に応じて全組み合わせへ広げる

営業日計算の現在の因子は次のとおりです。

| 因子 | 水準 |
| --- | --- |
| 国 | 日本、米国、英国 |
| 開始日の種類 | 営業日、週末、祝日 |
| 営業日数 | 1日、5日 |

期待する不変条件は「終了日が営業日」「開始日から終了日までに数えた営業日が入力値と一致」です。

## 4. 実行コマンド

```bash
npm test
npm run test:cui
npm run test:ct
npm run test:coverage
npm run verify
```

`npm run verify` はカバレッジ付き全テスト、フロントエンドビルド、Rustテストを順番に実行する統合ゲートです。

## 5. CI

Pull Requestと`main`へのpushでは、GitHub ActionsがmacOS上で`npm run verify`を実行します。ホストCIの成功はローカル実行の代替ではなく、両方を別の証拠として扱います。
