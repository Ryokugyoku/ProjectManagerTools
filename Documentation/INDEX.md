# Documentation Index

AI と開発者が、必要な仕様だけを短時間で見つけるための入口です。

| 文書 | 参照する場面 | 主な内容 |
| --- | --- | --- |
| [FOLDER_RULES.md](FOLDER_RULES.md) | ファイルの追加、移動、責務分割 | 現在の構成、配置先、分割条件、命名 |
| [LAYOUT_CONCEPT.md](LAYOUT_CONCEPT.md) | 画面、スタイル、文言、操作の変更 | UI の目的、構造、視覚言語、状態、レスポンシブ、品質基準 |
| [TEST_STRATEGY.md](TEST_STRATEGY.md) | 振る舞いを変えるコード、品質ゲート | リスク別検証、CUI、CT、カバレッジ、CI |

## 情報源の優先順位

判断が競合した場合は、次の順で扱います。

1. ユーザーの今回の明示的な指示
2. `AGENTS.md`
3. このディレクトリの仕様書
4. 現在のソースコードと設定
5. README の概要

仕様書は意図と制約、ソースコードは実装値の情報源です。実装値を変更した場合は、意味が変わる箇所だけ仕様書も更新します。

## 文書運用

- 既存文書に収まる内容のために新しい文書を増やさない。
- 実装の逐語的な説明ではなく、将来の判断に必要な理由と境界を残す。
- 未決定事項は推測で規約化せず、「未決定」と記す。
- 一時的な調査結果やビルド出力は `Documentation/` に置かない。
- 同じタスクで変更されていない文書を繰り返し読まない。
